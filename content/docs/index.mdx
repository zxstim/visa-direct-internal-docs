## The VISA Direct transaction model

Visa Direct enables anyone with a Visa card to send funds to anyone with a Visa card or a bank account.

### Visa Direct / Standard transaction overview

```
┌──────────────┐     ┌──────────────┐     ┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│  Mobile App  │ ──▶ │   Acquirer   │ ──▶ │     Visa     │ ──▶ │    Issuer    │ ──▶ │   Recipient  │
│              │     │              │     │              │     │              │     │              │
│Sender        │     │Captures &    │     │Authorize &   │     │Recipient     │     │Receives      │
│initiates     │     │routes        │     │settle        │     │bank          │     │funds         │
└──────────────┘     └──────────────┘     └──────────────┘     └──────────────┘     └──────────────┘
```

### PVCOMBANK / Tourist App use case

```
┌──────────────┐     ┌──────────────┐     ╔══════════════╗     ┌──────────────┐     ┌──────────────┐
│   Tourist    │ ──▶ │   PVCB App   │ ──▶ ║     Visa     ║ ──▶ │ Tourist VND  │ ──▶ │  Vietnamese  │
│              │     │              │     ║              ║     │   Account    │     │   Merchant   │
```

> **AFT (Account Funding Transaction):** pulls funds from the sender's foreign card.
> **OCT (Original Credit Transaction):** pushes funds to the recipient account.

## End-to-end Visa Direct operating chain

Designed as one continuous operating chain, not isolated API calls.

### Transaction steps

1. **Capture sender intent** — App collects sender, recipient, amount and required KYC / purpose fields.
2. **Authorize AFT** — Submit AFT with sender, receiver and use-case data; receive issuer response, get transaction approval/decline.
3. **Pre-Fund transaction** — If AFT is approved then pre-fund the customer account, then wait for VISA settlement to repay the pre-fund.
4. **Receive Settlement from Issuer** — Receive T+n settlement from Issuer, reconcile and clear the transaction, then refund the pre-funded transaction.
5. **Notifications, logs, history** — Manage user notifications, list transaction history, store audit trail, prepare exceptions and support views.

### Operational foundations / cross-cutting requirements

- **Clearing file** — Adjust clearing file logic so Visa Direct transactions map correctly into finance, fees and recon.
- **Settlement & treasury** — Confirm settlement timetable, prefunding and liquidity controls, and BIN-level monitoring.
- **Exceptions & reversals** — If a push fails, reverse or return funds using the correct mechanism and preserve response data.
- **Support & MI** — Operational dashboards, issuer-decline analysis, customer support workflows and regulatory reporting.

> **Liquidity prerequisite:** all transactions operate on advanced funding. Acquirer must allocate enough funds for 2-3 days of expected transaction volumes.

## Project Objectives

Prerequisites that convert the idea into an approved Visa program.

1. **Business case & PIF inputs** — Size volumes by corridor, define use cases, name program parties, describe customer journey and risk controls.
2. **PIF / program approval** — Submit or update the Program Information Form. Visa due diligence covers AML, sanctions, credit, settlement risk and brand review.
3. **BIN strategy** — Request or enable a dedicated BIN for Visa Direct activity; confirm processor / switch support and routing tables.
4. **Contract stack** — Lock contracts with KYC / passport processing provider, processor, fraud tools and any service providers needed for launch.
5. **Production onboarding** — Move from sandbox credentials to certification / production credentials, including certificates and encryption setup.
6. **Brand & marketing approvals** — Share the marketing plan, claims and any Visa brand usage for approval before public launch.

> **Change control:** if the program later changes sending countries, processor or business relationships, or marketing / branding, Visa may require a new PIF approval cycle.

## Testing, certification and production readiness gates

Disciplined stage-gate approach reduces launch risk and prevents avoidable issuer declines or finance breaks.

### Stage gates

1. **Gate 1 — Design review** — Use cases, PIF assumptions, BIN design, data fields, ledger mapping.
2. **Gate 2 — Sandbox connectivity** — Mutual SSL, certificates, encryption, test credentials, API connectivity.
3. **Gate 3 — Functional certification** — AFT, OCT, error handling, reversals, issuer responses, KYC edge cases.
4. **Gate 4 — UAT + ops sign-off** — Clearing, settlement, monitoring, support, reconciliations, reporting.
5. **Gate 5 — Production pilot** — Low-volume launch with daily KPI review, issue triage, go / no-go control.

### Entry criteria for certification

- Approved program scope and environment access
- Test data and issuer / processor support aligned
- Clearing, settlement and MI design documented
- KYC / AML controls connected into the flow

### Exit criteria for production pilot

- End-to-end pass rate at agreed threshold
- Finance reconciles each transaction leg and fees
- Support runbooks, incident process and dashboards live
- Visa and internal go-live approvals complete

### Pilot discipline

- Limit pilot merchants, channels and corridors at start
- Daily review of issuer declines and funds availability
- Monitor KYC fails, fraud alerts and customer complaints
- Scale only when metrics stabilize and gates pass

## Go-to-market, issuer readiness and pilot KPIs

First launch is a measured production pilot supported by Visa-aligned marketing and daily performance management.

### Launch checklist

- Share the marketing plan and any Visa brand claims and creative for approval
- Confirm the production BIN is active, routed, monitored and not being declined because of issuer readiness gaps
- Train operations and customer support on funding failures, OCT declines, reversals and KYC exceptions
- Publish incident-management and escalation paths with Visa, processor and key internal teams
- Start with limited corridors, channels and partners before broad public activation

### Pilot KPIs

1. **Authorization & OCT success rate** — By corridor and issuer.
2. **Time to funds available** — And percentage requiring reversal or manual handling.
3. **KYC pass rate** — Manual review rate and onboarding conversion.
4. **Fraud, suspicious activity** — Cases and complaint rate.

> **Go / no-go scaling rule:** scale only when the pilot meets agreed thresholds for approval, KYC conversion, finance reconciliation, fraud and CX. If unstable, fix first; do not expand marketing spend.
